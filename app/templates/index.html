THE DELIVERY LOOP

A clear path to production.

Every change has a route from review to a running service.

01SOURCE

Review the change

Changes arrive through a pull request targeting main.

→
02VERIFY
✓

Run the checks

GitHub-hosted CI runs pytest and confirms the Docker image builds.

→
03PUBLISH

Publish the image

A passing change on main publishes a commit-tagged image to Docker Hub.

→
04OPERATE
⌁

Deploy and verify

A self-hosted runner updates Compose and waits for the container health check.
